# P2.2 - Consent Mode v2 adapter + consentMode key

Row: `- [~] (A) P2.2 - Consent Mode v2 adapter + consentMode key (plan: Google Consent Mode v2)`

Tier: A

## Why

Consent Mode is how a Google tag learns what it may do, so the `default` command must say
"denied" for every optional key before any tag can read it, and only the core's state may move a
key to "granted". The adapter pushes `default` synchronously at install (required keys granted,
`extra` as configured), then an `update` only when the mapped values change, through
`window.dataLayer` as `arguments` objects, which is the shape gtag.js reads. Like the gate it is a
separate entry importing the core as `./index.js` and does nothing without its config key.
`consentMode` joins schema version 1 additively; validation enforces one owner per gtag key,
mapping or `extra`, and that mapped categories exist (decision #48). Wiring into the Astro
integration and the demo's `dataLayer` stub is P2.3.

## Review 1

### Findings

No P1 or P2 findings.

- **P3** `CHANGELOG.md` (Unreleased, Consent Mode entry): says `update` is pushed "on every
  change", but the code and decision #47 push it only when the mapped payload differs (README is
  correct). Reword to "whenever the mapped values change".
- **P3** `src/astro/validate.ts` `LATER_KEYS`: now an empty map, so the "added in vX" message path
  is unreachable and untested. Keep it deliberately for future keys (say so in a comment) or drop
  it.

### Questions

- A gtag key that is neither mapped nor in `extra` is absent from the `default` command, and
  Google tags treat an unset consent type as not restricted. The plan does not require every key
  to be covered, so this is the site's configuration responsibility, but a validation warning for
  unmapped keys (or a README note) would make the gap visible. Worth a decision entry?
- The adapter captures the `window.dataLayer` array at install. A site whose own snippet
  reassigns `window.dataLayer = []` (rather than `||= []`) after install would orphan later
  `update` pushes. Google's snippet does not do this; a README line may be enough.
