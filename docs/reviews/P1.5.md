# P1.5 - Record hook

Row: `- [~] (A) P1.5 - Record hook: function and URL forms (plan: Record)`

Tier: A

## Why

The record is the only network request the package can make, so it is wired to the state
machine's commit hook and nowhere else: it can only fire after a state-establishing or
state-changing choice, never at mount, on a no-op or on a non-blocking close. The payload is
assembled from the committed choice and the resolved locale only, with no identifier, user agent
or page. A function recorder owns its transport; the URL form tries `sendBeacon` and falls back
to `fetch` with `keepalive`. Every failure path (throwing or rejecting recorder, refused or
throwing beacon, rejected or throwing fetch) is swallowed so recording can never block or undo
the visitor's choice. Also folds in two P1.4 review advisories: unknown `buttons.order` entries
are ignored at runtime, and the locale-switch test asserts explicit string lists.

### Findings

No P1 or P2 findings.

- P3 - `src/core/record.ts`: a cross-origin record URL receives an `application/json` body, which
  is not a CORS-safelisted content type, so the browser preflights the `fetch` fallback (and some
  engines refuse such a `sendBeacon` outright, which the code already handles by falling back).
  Worth one sentence in the README's record section (P1.8) telling sites that a cross-origin
  endpoint must answer the preflight; same-origin endpoints are unaffected.
- P3 - `test/unit/record.test.ts`: "no request on a no-op or before a choice" only asserts after
  the no-op; the before-a-choice half is implied by the same assertion covering mount, but an
  explicit `expect(h.sendBeacon).not.toHaveBeenCalled()` right after `mount` would make the intent
  self-evident.

### Questions

- The plan's Choice order is "writes the cookie, dispatches the change, records and closes"; the
  runtime closes the UI before publishing (pre-existing, P1.3) and records after publishing. The
  visitor-observable contract is unaffected; noted only so the ordering is a conscious choice.

### Checked

- Recording is wired only to the commit hook: no call at mount, on a no-op, or on a non-blocking
  close (tests cover function and URL forms).
- Payload is exactly `action`, `categories`, `policyVersion`, `packageVersion`, `locale`, `at`;
  `locale` is the resolved locale; categories are a copy; no identifier, user agent or page.
- URL form: `sendBeacon` with an `application/json` Blob, falling back to `fetch` (`POST`,
  `keepalive`) when `sendBeacon` is missing, throws or returns `false`; `sendBeacon` is called with
  `navigator` as receiver.
- Every failure path (throwing or rejecting recorder, throwing beacon, throwing or rejecting
  fetch, missing `fetch`, missing `defaultView`) is swallowed by the inner `catch` handlers or the
  outer `try`; the choice still stands.
- No new CSP-relevant API; no dependency added; decision #33 records the request shape the plan
  left open; CHANGELOG updated; tests use `example.com` only.
- Folded P1.4 advisories: unknown `buttons.order` entries are dropped at runtime with a test;
  locale-switch test asserts explicit string lists.
