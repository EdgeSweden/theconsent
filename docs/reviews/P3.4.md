# P3.4 - Gate keeps the async attribute as written, v0.2.2

Row: `- [~] (A) P3.4 - Gate: keep the async attribute as written, document data-astro-exec, local tag v0.2.2 (plan: Script gating, Releases)`

Tier: A

## Why

A review of v0.2.1 found that the gate set `live.async = true` on every classic script, which
also adds a visible `async` attribute (and changes `document.currentScript.async`) on scripts
that never had one, breaking the README's "same attributes" promise. Leaving classic scripts
untouched is enough: an inserted classic script is async by default and stays out of the
browser's in-order list, so decision #55's ordering guarantee still holds (the slow-module and
never-loading-module browser tests still pass). Only a module without `async` gets
`async = false`. A new Chromium test compares `hasAttribute("async")` and `type` on five kinds of
script; it fails on the v0.2.1 gate and passes now. The README documents `data-astro-exec` as the
one attribute a live script gains, and the 0.2.1 CHANGELOG wording about modules is corrected in
place (decision #59). The version is 0.2.2; the tag follows on `main` after the merge.
