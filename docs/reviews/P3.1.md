# P3.1 - Adapter typings without Astro

Row: `- [~] (A) P3.1 - Adapter typings that do not require Astro, with a packed-consumer type check (plan: Repository layout, Adapters)`

Tier: A

## Why

A post-release review of v0.2.0 found that `dist/gate.d.ts` and `dist/gtag.d.ts` imported
`ConsentConfig` from `./astro.js`, whose declarations import `astro`, an optional peer. A
TypeScript project without Astro failed with `Cannot find module 'astro'` on importing either
adapter. Moving the adapters' type imports to the core entry was not enough: the declaration
bundler shares types across all entries of one build and still chose `./astro.js`. The browser
entries and `./astro` are now two tsup builds (decision #53), and `check:size` packs the tarball
and type-checks `.`, `./gate` and `./gtag` from a temporary consumer that has zod but not Astro.
That check reproduces the reported error against the v0.2.0 build config and passes now.

### Findings

No P1 or P2 findings.

- P3 `scripts/check-consumer-types.ts`: `pnpm pack` runs with `stdio: "ignore"` and the catch
  suppresses any error that has a `status`, so a failing pack (for example a missing `dist/` when
  `pnpm size` runs without a build) prints only "packed typings failed to type-check without astro
  installed", which misattributes the cause. Let pack's stderr through, or report which step failed.
- P3 `scripts/check-consumer-types.ts`: the packed check covers `.`, `./gate` and `./gtag` only;
  `dist/astro.d.ts` is now a separately bundled declaration (it inlines its own copy of the schema
  types) and nothing type-checks it as shipped. A second consumer with Astro installed importing
  `@edgesweden/consent/astro` would close that gap cheaply.

### Evidence

- Scratch copy with the `main` tsup config and adapter sources: `dist/gate.d.ts` imports
  `./astro.js` and the new script fails with `Cannot find module 'astro'` (exit 1), so the check
  is a real regression test.
- Branch build: `gate.d.ts` and `gtag.d.ts` import only `./index.js` and `zod`; `index.d.ts` uses a
  shared `schema-*.d.ts` chunk that imports only `zod`. Same consumer also passes with
  `module`/`moduleResolution: NodeNext`.
- Runtime output versus a `main` build: `index.js`, `astro.js`, `styles.css` byte-identical;
  `gate.js`/`gtag.js` differ only in minifier identifiers. `./astro` exports the same names. No
  public contract, dependency or CSP surface changes.
- CHANGELOG (Unreleased, Fixed) and decisions #52, #53 present; board rows P3.2 and P3.3 added per
  decision #52.
