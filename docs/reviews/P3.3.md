# P3.3 - Astro ClientRouter support, v0.2.1

Row: `- [~] (A) P3.3 - Astro ClientRouter support (reattach UI, republish state, rescan gated scripts), local tag v0.2.1 (plan: Astro integration, Runtime behaviour)`

Tier: A

## Why

The post-release review found that with Astro's `<ClientRouter />` the first navigation removed
the consent UI for good: the router replaces `<body>` and the `<html>` attributes, and bundled
modules do not run again, so the banner and settings dialog were detached, the reopen control
did nothing, `data-consent-<id>` vanished and gated placeholders on later pages never ran. The
core and the gate now handle `astro:after-swap` without new public API (decision #56), which
keeps this a patch: the UI is destroyed (including its document focus guard) and rebuilt on the
new body in the page's locale, the attributes are re-applied, and the gate rescans while loading
an external script at most once per document. A third demo build uses the ClientRouter
(decision #57); its four e2e tests prove the navigation is client-side and fail against the
v0.2.0 core. The core grows to 5.75 kB of 6 kB. The version is 0.2.1 with all three fixes under
one CHANGELOG entry; the tag follows on `main` after the merge.

## Review 1

### Findings

**P1 - A gated script first reached by client-side navigation runs twice.**
Location: `src/gate/index.ts`, the `astro:after-swap` listener (`doc.addEventListener("astro:after-swap", onReady)`).
Violated requirement: plan, Script gating ("A script is never run twice"); decision #56 ("an
external gated script is loaded at most once per document").
Scenario: Astro dispatches `astro:after-swap` inside `updateDOM` and only afterwards, in
`updateCallbackDone.finally`, calls `runScripts()`, which re-creates every `<script>` without
`data-astro-exec` and with no type, `text/javascript` or `module` (astro 7.4.1,
`dist/transitions/router.js`). The gate's pass on `after-swap` queues the activation, the live
script it inserts carries no `data-astro-exec` (Astro only marked placeholders it had seen before),
so `runScripts()` clones it and the browser executes it a second time. Reproduced in a scratch copy
of the router demo: with analytics accepted on `/`, a placeholder
`<script type="text/plain" data-consent="analytics" src="/demo/extra.js">` present only on
`/cookies/` gives `demoRan = [..., "extra", ..., "extra"]` after one navigation (one request,
two executions). An inline gated script hits the same path whenever it is activated before
`runScripts()` (here it escaped only because the chain was waiting for `extra.js` to load). For a
real vendor tag this means a double page view or double initialisation. The four e2e tests miss it
because every demo placeholder already exists on the first page, so the gate dedups it before
Astro can see it.
Smallest safe fix: rescan on `astro:page-load` (dispatched after `runScripts()`; also fires on
the initial load, which `claimed` already makes harmless) instead of `astro:after-swap`; update
decision #56's wording in a superseding entry if the event name is part of it.
Regression test: e2e on the router build with a gated external and a gated inline placeholder that
exist only on a page reached by navigation, category granted before navigating; assert each ran
exactly once (and a unit test that the gate does not act on `astro:after-swap` / acts on
`astro:page-load`).

**P2 - A queued external script whose placeholder is swapped out before activation never runs
again in the document.**
Location: `src/gate/index.ts`, `pass()` adds `placeholder.src` to `ran` when queueing, while
`activate()` silently returns for a disconnected placeholder.
Violated requirement: plan, Script gating (every granted placeholder is replaced by a live
script); decision #56 (at most once, not zero times).
Scenario: on page A the visitor clicks Accept all; the chain waits for a slow earlier external
classic script, the visitor follows a link before it loads, the router swaps the body, the queued
placeholder for `vendor.js` is now disconnected and `activate()` returns without inserting it; on
page B (and every later page) the `vendor.js` placeholder is skipped because `ran` already holds
its URL, so a granted script never runs until a full reload.
Smallest safe fix: record the URL in `ran` inside `activate()` at the point the live script is
actually inserted (and check `ran` there as well as in `pass()`), so a dropped activation does
not count.
Regression test: unit (happy-dom) with a never-loading first external script and a second
external script, grant, replace `<body>` with a copy containing the second placeholder, dispatch
the swap/page-load event, resolve the first script, and assert the second is activated once.

**P3 - README overstates the parallel with Astro's inline scripts.** `README.md`, "Astro's
ClientRouter": Astro does not re-run an inline script whose text it has already executed unless it
has `data-astro-rerun` (`deselectScripts`), so "inline gated code runs on each page, like Astro's
own inline scripts" describes the opposite of Astro's default. State only what the gate does.

**P3 - Duplicate external placeholders on one page now collapse to one.** With `ran`, two
placeholders with the same `src` on the same page (e.g. one per category) activate only the
first, a change from v0.2.0 outside the ClientRouter path. Worth one line in the CHANGELOG/README
or limiting the dedup to placeholders that arrive after a swap.

## Review 2

### Findings

**P3 - "per page" vs "per document".** `README.md`, Script gating: "An external script URL is
loaded at most once per page" while the ClientRouter section, the CHANGELOG and decision #58 say
"per document". Under the ClientRouter a "page" is a navigation, so the Script gating sentence
reads as if the URL could load again on the next page. Say "per document" there too.

No P1 or P2.

### Review 1 findings

- P1 (double execution): resolved. The gate rescans on `astro:page-load`, which astro 7.4.1
  dispatches after `runScripts()` (`dist/transitions/router.js`), and every live script carries
  `data-astro-exec`, which `runScripts()` skips; that also covers an activation from a choice
  made between the swap and `page-load`. On the initial load `page-load` fires from `window`
  `load` and `claimed` makes the extra pass a no-op. With the Review 1 gate restored in a scratch
  copy, the new e2e test "runs exactly once" fails (as does the updated "not loaded again" test),
  and all three new `swap.test.ts` tests fail; with the fix they pass.
- P2 (URL blocked by a detached queued placeholder): resolved. `ran` is checked and written in
  `activate()` after the `isConnected` check, so a dropped activation does not record the URL; the
  unit test holds the chain on a slow `<head>` script across a swap and asserts the second page's
  placeholder activates.
- P3 (README parallel with Astro inline scripts): resolved; the sentence is gone.
- P3 (same-URL collapse on one page): resolved by documentation in README, CHANGELOG and
  decision #58.
- Question (silent locale change): answered in README and decision #58.

Regression surfaces checked: the core still rebuilds the UI on `astro:after-swap` (unchanged by
the fix); the disposer removes the `page-load` listener; a same-URL second placeholder stays
`text/plain` and does not stall the chain; decision #58 supersedes only the gate part of #56.
