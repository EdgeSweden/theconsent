# P1.7 - Demo site + e2e suite

Row: `- [~] (B) P1.7 - Demo site + e2e suite with axe and CSP assertions (plan: Demo, Tests)`

Tier: B

## Why

The unit suite runs in happy-dom, which has no real `inert`, focus model, CSP, cookie jar or
layout; the e2e suite is where those guarantees are proven in Chromium against what a site
actually ships. The demo is neutral (local pages, `example`-free copy, no external requests) and
bilingual by `<html lang>`, with a record list fed by a function recorder, a footer reopen
control and a `withdraw()` button. Every test inherits the fixture that fails on any CSP
violation, and the demo's CSP adds `default-src 'self'` so a stray request would also be a
violation. Non-blocking mode needs a second build of the same pages (decision #38). Gated
scripts and the Consent Mode stub arrive with the adapters in P2.3. The suite passed 120/120
with `--repeat-each=5`.

### Findings

No P1 or P2 findings.

- P3 `test/e2e/consent.spec.ts:269` - "the language switch changes every string" asserts only the
  settings dialog's `button, label, h2` texts; category/service descriptions, the banner copy and
  the link label are not compared, so the test name overstates what it proves. Assert the
  dialog's full text (or each description) against the `sv` strings.
- P3 `test/e2e/consent.spec.ts:292` - the reduced-motion test checks `animationName` on the banner
  only; the plan says "no transitions", and `src/styles.css` has transitions (switch background
  and knob) that are not asserted. Add a `transitionDuration` check on a switch.
- P3 `test/e2e/consent.spec.ts:216` - the second `withdraw()` no-op is proven only by the record
  list; asserting the cookie's `t` is unchanged would also prove "nothing is written".
- P3 `test/e2e/consent.spec.ts:56` - equal prominence compares height and vertical position only;
  comparing width (or computed font/colour) would make the parity check harder to regress.
- P3 `test/e2e/smoke.spec.ts` - now overlaps the new suite and finds the banner by the substring
  "Cookies"; fold it into `consent.spec.ts` or use the exact dialog name.
- P3 docs - the deferral of the plan's Demo items (gated scripts, Consent Mode stub) and the e2e
  item "required gated script runs / required Consent Mode key granted" to P2.3 is stated only in
  this file's Why; the P2.3 row covers it, but a `docs/decisions.md` line would make it durable.
