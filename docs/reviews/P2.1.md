# P2.1 - Script-gating adapter + gateScripts key

Row: `- [~] (A) P2.1 - Script-gating adapter + gateScripts key (plan: Script gating, Version boundary)`

Tier: A

## Why

Gating is the mechanism that actually keeps an optional third-party script from running before
consent, so it activates only from the core's `onConsent` state: never from the cookie, never
for a denied category, and once per placeholder. It is a separate entry that imports the core as
`./index.js` rather than bundling a copy, because a copy would carry its own runtime and never see
the state `mount` created (decision #42); the bundle-import check and the 1 kB budget now cover
`dist/gate.js`. `gateScripts` joins schema version 1 additively and defaults to `false`, and the
adapter itself does nothing without it, so upgrading cannot switch gating on. Wiring the adapter
into the Astro integration and the demo is P2.3.

### Findings

**P2-1. Gated scripts lose their document order; dependent scripts break.**

- Location: `src/gate/index.ts`, the activation loop (`createElement("script")` + attribute copy +
  `replaceWith`).
- Requirement: plan, Script gating: the live script has "the same `src`, attributes and text".
  A parser-inserted `<script src>` without `async` runs in document order; a script created with
  `createElement` is force-async, so copying the attributes does not preserve that semantics, and
  inline code runs synchronously on insertion, before any earlier external script has loaded.
- Failure scenario: a site gates a library and its initialiser in one category,
  `<script type="text/plain" data-consent="analytics" src="/js/lib.js">` followed by
  `<script type="text/plain" data-consent="analytics">Lib.init()</script>`. On grant the inline
  script runs first and throws `ReferenceError: Lib is not defined`; analytics silently never
  initialises. Probed in Chromium (scratch copy, same activation logic) with three placeholders in
  document order slow external, fast external, inline: execution order was `inline,fast,slow`.
- Smallest safe fix: when the placeholder has no `async` attribute and has a `src`, set
  `live.async = false` so external scripts execute in insertion order; for inline code that follows
  a gated external script, either defer its insertion until the preceding non-async external
  scripts in the same pass have fired `load`/`error`, or state the limit explicitly in the README
  (and a decision entry) with the recommended pattern (put the init code in the external file or
  use `data-type="module"` with `import()`). The first half is required either way.
- Regression test: an e2e (or a unit test asserting `live.async === false` for a placeholder
  without `async`, and `true`/attribute present when it has one) plus, if ordering of inline code
  is implemented, an e2e with a slow external followed by an inline consumer asserting order.

**P2-2. Installed before the body is parsed, the gate never activates stored grants.**

- Location: `src/gate/index.ts`, `onConsent` callback runs `doc.querySelectorAll` only on consent
  states; README "Elsewhere, call it yourself after `mount`".
- Requirement: plan, Script gating ("on each grant, every ... whose category is granted is
  replaced"; "Required categories are processed at mount"). The core already handles a missing
  `<body>` by deferring to `DOMContentLoaded` in `mount`, so running from `<head>` is a supported
  host shape.
- Failure scenario: a non-Astro site loads a classic bundle in `<head>` that calls
  `mount(config); installScriptGating(config)`. The initial state is published while the body is
  unparsed, so `querySelectorAll` finds no placeholders. A returning visitor with a valid stored
  grant makes no new choice, so no further state arrives: their granted scripts, and on every visit
  the required-category scripts, never run.
- Smallest safe fix: when `doc.readyState === "loading"`, keep the latest state and re-run the
  same activation pass once on `DOMContentLoaded` (removed by the disposer).
- Regression test: unit test with the document in the loading state (stub `readyState`), install
  - mount with a stored grant, append placeholders, dispatch `DOMContentLoaded`, assert the granted
    and required placeholders are activated and the denied one is not; and that disposing before
    `DOMContentLoaded` activates nothing.

**P3-1.** README "Script gating" says the Astro integration installs the adapter for you; that
wiring lands in P2.3, so until then `gateScripts: true` in an Astro site does nothing. Fine if
P2.3 follows before the tag; otherwise word it as "from v0.2.0".

**P3-2.** The `WeakSet` in `installScriptGating` is redundant: an activated placeholder is
removed from the document by `replaceWith`, so `querySelectorAll` cannot return it again. Keep it
only if it is meant as a defence against a throwing `replaceWith`; otherwise drop it to save
bytes.

### Findings

**P2-1. A gated external script that the browser never fetches stalls the chain for good.**

- Location: `src/gate/index.ts`, `activate`: `ordered = live.src !== "" && !placeholder.hasAttribute("async")`
  and the `done` promise that resolves only on `load`/`error`.
- Requirement: plan, Script gating ("every ... whose category is granted is replaced"); README and
  decision #44 ("run in page order, as if they had never been gated"). A parser-inserted script that
  is not executed is simply skipped; it does not block later scripts.
- Failure scenario: the browser fires neither `load` nor `error` for a script it does not prepare:
  a classic script with `nomodule` in any module-capable browser, or a `data-type` that is not a
  JavaScript MIME type or `module`. Probed in Chromium (scratch page, `createElement` +
  `async = false` + append): `nomodule src` and `type="text/x-foo" src` both time out with no
  event; a plain `src` fires `load`. So a site that gates a module/legacy pair
  (`data-type="module" src="/a.mjs"` then `nomodule src="/a-legacy.js"`, the usual legacy-build
  output) gets the module script and then nothing else, ever: every later placeholder, including
  ones in other categories granted later in the session, stays inert silently. The same happens
  for the required-category scripts placed after it on every page load.
- Smallest safe fix: only wait when the browser will actually fetch and run the script, e.g.
  `ordered = live.src !== "" && !placeholder.hasAttribute("async") && !(live.noModule && type !== "module") && (type === null || type === "" || type === "module" || /^(text|application)\/(x-)?(java|ecma)script$/i.test(type))`,
  or the simpler `!placeholder.hasAttribute("nomodule")` plus an explicit list of executed types.
  A bounded fallback (resolve after a timeout) is an alternative but changes ordering semantics.
- Regression test: unit test with an ordered external `nomodule` placeholder (and one with
  `data-type="text/x-template"` and `src`) followed by an inline placeholder; on grant, without
  firing any event, the inline placeholder is activated.

**P3-1.** A throw inside `activate` (for example `setAttribute` rejecting a parser-accepted
attribute name) rejects `chain`, after which every later `.then` is skipped, the same silent stall
as above. Consider `chain = chain.then(() => activate(placeholder)).catch(() => {})` or equivalent,
if the bytes allow.

**P3-2.** The `DOMContentLoaded` test uses `ALL_GRANTED` only. Review 1 asked for a denied
placeholder that stays inert after the extra pass and for a dispose-before-`DOMContentLoaded` case
that activates nothing; both are cheap to add.

**P3-3.** `CHANGELOG.md` does not mention the page-order guarantee or the `DOMContentLoaded` pass,
both of which are user-visible behaviour now documented in the README.

### Findings

**P3-1.** `runs` is slightly looser than the browser's rule in rare shapes: a whitespace-only
`data-type` (the code trims it to empty and waits; the browser strips it to `""`, which matches no
type, so it never runs, never fires an event and stalls the chain), and a copied `language`,
`event`/`for` attribute that stops a classic script from running. Conversely
`data-type="module" nomodule` runs but is not waited on (ordering only). None is a realistic
placeholder; if desired, test the raw value for emptiness before trimming and treat
`nomodule` as skip only for classic scripts.
