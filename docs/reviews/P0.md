# P0 - Repository tooling

Row: `- [~] (A) P0 - Repository tooling: package.json, tsup, vitest, eslint, prettier, size-limit, Playwright + axe, pnpm check, release:check, docs (plan: Repository layout, Checks)`

Tier: A

## Why

Every later package is judged against `pnpm check`, so the gate has to exist, run every named
check for real and stop at the first failure before any product code lands. The CSP bans live in
eslint from the start so no browser-bundle code can be written without them, and a unit test
proves each ban fires on `src/core`, `src/gate` and `src/gtag` while type-only imports of the
build-time schema stay allowed. `check:e2e` runs against a one-page demo under Astro's CSP with a
fixture that fails any test on a CSP violation, so the zero-violation assertion is in place before
the banner exists. `release:check` encodes the release refusal rules now so P1.8 only has to run
it.

## Review 1

Reviewed `git diff main...chore/tooling` against the plan (Repository layout, Checks, Size budget,
Releases, Delivery > Safety). `pnpm check` re-run by the reviewer on Node 24.11.1: all eight checks
green. The `docs/plan.md` changes on the branch are Prettier reformatting only. Probes below were
run in a scratch copy of the branch; the repository was not modified.

### Findings

**P2-1. Nothing verifies that the browser entry has zero runtime dependencies; a transitive zod
import ships in `dist/index.js` and passes every check.**

- Location: `.size-limit.json` (uses `@size-limit/file`), `tsup.config.ts`
  (`external: ["astro", "zod", /^node:/]`), `eslint.config.js` (the zod/astro import ban applies
  only to `src/core/**`, `src/gate/**`, `src/gtag/**`).
- Requirement: plan, Repository layout: "The browser bundles therefore have zero runtime
  dependencies, which the size budget verifies." Delivery > Safety: "The browser entries (`.`,
  `./gate`, `./gtag`) have zero runtime dependencies."
- Failure scenario (reproduced): add `src/shared/schema.ts` with `import { z } from "zod"` and
  import it from `src/core/index.ts`. `eslint src` passes (the file is outside the banned
  directories), `tsup` emits `import {z} from 'zod'` into `dist/index.js` because zod is external,
  and `size-limit` reports 201 B gzipped because the file plugin does not follow imports. Every
  site that imports `@edgesweden/consent` then bundles zod into its browser code. The same holds
  for any other dependency added later, which tsup externalises by default.
- Smallest safe fix: after `tsup` in `check:build` (or as part of `check:size`), assert that every
  import/export specifier in each browser entry (`dist/index.js` now; `dist/gate.js`,
  `dist/gtag.js` in v0.2) is `./styles.css` or otherwise relative to `dist/`, and fail otherwise.
  Alternatively switch the `.` budget to `@size-limit/esbuild` so imports are bundled and counted,
  but that only catches dependencies large enough to break 6 KB, so the specifier assertion is the
  real guard.
- Regression test: a unit test for the assertion function that rejects a sample bundle containing
  `import{z}from"zod"` and accepts one whose only import is `./styles.css`; plus the assertion
  itself running on the real `dist/` inside `pnpm check`.

**P2-2. `release:check` refuses every release because `CHANGELOG.md` is never packed.**

- Location: `package.json` `files: ["dist"]` together with `scripts/release-check.mjs`
  (`for (const required of [..., "CHANGELOG.md"])`).
- Requirement: plan, Releases: `pnpm release:check` refuses only on an unclean tree, a missing
  CHANGELOG entry for the version, or packed files outside `dist/`, `package.json`, `README.md`,
  `LICENSE`, `CHANGELOG.md`. The P0 row delivers a working `release:check`.
- Failure scenario (reproduced): `pnpm pack --dry-run --json` lists `dist/*`, `LICENSE`,
  `package.json`, `README.md` and no `CHANGELOG.md` (pnpm does not auto-include it). At P1.8,
  with a clean tree and a correct `## [0.1.0] - YYYY-MM-DD` entry, `release:check` still fails
  with `pack is missing CHANGELOG.md`, so the release step cannot complete without changing the
  release gate during a release package.
- Smallest safe fix: add `"CHANGELOG.md"` to `files` in `package.json` (the plan allows it in the
  packed set and it is useful to consumers). Do not drop the check silently instead.
- Regression test: factor the refusal rules in `scripts/release-check.mjs` into a pure function
  over `{ status, version, changelog, packedFiles }` and unit-test each refusal and the pass case;
  add a test (or a check in the script that `pnpm check` exercises) that the `files` field plus
  pnpm's auto-included files yields `CHANGELOG.md`. Today `release:check` has no test at all.

**P3-1. CSP lint bans are bypassable in ways an implementer could hit by accident.** Verified as
not flagged in `src/core`: ``el.setAttribute(`style`, …)`` (template literal), a variable holding
`"style"` passed to `setAttribute`, `createElement("STYLE")`, `el.setHTMLUnsafe(…)`,
`new DOMParser().parseFromString(…, "text/html")`, `iframe.srcdoc = …`. The e2e zero-violation
fixture is the real guarantee (verified: an inline `style` attribute in the demo fails the smoke
test with `style-src-attr`), but the last three are "HTML in strings" (Principles 3), which the
e2e assertion does not catch. Consider adding `setHTMLUnsafe`, `parseFromString`, `srcdoc` to
`no-restricted-properties` and matching the `style` selectors case-insensitively and on
`TemplateLiteral` quasis.

**P3-2. `"./package.json"` is exported although the plan's `exports` list is `.`, `./astro`,
`./styles.css`.** Harmless and conventional, but `exports` is a Tier A public contract; record it
in `docs/decisions.md` or remove it.

**P3-3. The browser-only `globals` override for `src/core/**` etc. has no effect.** Flat-config
`languageOptions.globals` merge, so Node globals from the earlier block remain, and
typescript-eslint disables `no-undef` for TS files anyway. Remove the line or replace it with a
`no-restricted-globals` list (for example `process`, `Buffer`, `require`) if Node globals in
browser code should fail.

### Questions

- The demo CSP emitted by Astro is `script-src 'self' 'sha256-…'; style-src 'self'` with no
  `default-src` or `connect-src`, so a pre-choice request is not blocked or reported by the CSP.
  That matches the plan's example policy and the "no request before a choice" e2e is planned as
  a network assertion in P1.7; confirm that is the intent rather than relying on CSP reports.

### Review 1 findings

- **P2-1 resolved.** `check:size` now runs `scripts/check-bundle-imports.ts` before size-limit
  (decision #9). Reproduced the Review 1 scenario (`src/shared/schema.ts` importing zod,
  re-exported from `src/core/index.ts`): eslint still passes, but the check fails with
  `dist/index.js: imports runtime dependencies: zod`. `test/unit/bundle-imports.test.ts` covers
  named, default, namespace, side-effect, re-export, `export *`, dynamic and parent-relative
  imports, plus the stylesheet-only pass case.
- **P2-2 resolved.** `CHANGELOG.md` is in `files`; the refusal rules are a pure function in
  `scripts/lib/release-rules.ts` with a unit test per refusal and the pass case, and a test asserts
  `pnpm pack` includes every required top-level file. In a clean scratch repository
  `release:check` now refuses only on the missing `## [0.0.0]` entry, as intended.
- **P3-1 addressed.** `setHTMLUnsafe`, `parseHTMLUnsafe`, `parseFromString`, `srcdoc`,
  `new DOMParser`, case-insensitive and template-literal `style` arguments, `setAttributeNS` and
  string timers are banned and tested; ordinary attributes, elements and timers stay allowed. A
  `style` name held in a variable is still not caught (static lint limit; the e2e CSP fixture
  remains the guarantee).
- **P3-2 resolved.** `./package.json` removed from `exports`; the exports now match the plan.
- **P3-3 resolved.** The ineffective `globals` override was removed.
- **Question resolved.** Decision #10 adds `default-src 'self'` to the demo CSP; verified in the
  built `examples/astro/dist/index.html`. This tightens, not weakens, the CSP.

### Findings

**P3-1. `engines.node` is `>=22` but the scripts now need Node >= 22.18.** Decision #8 relies on
unflagged type stripping; on Node 22.0 to 22.17 `pnpm check` and `release:check` fail with an
unknown-extension error. The failure is loud, so advisory: state the requirement in the README or
a contributor note (raising the package's `engines` would also constrain consumers, so keep that
separate).

**P3-2. `check-bundle-imports` accepts any `./` import without scanning it.** Correct today because
`tsup` uses `splitting: false`, so the only relative import is `./styles.css`. If a later package
enables splitting for the v0.2 entries, a shared `./chunk-*.js` could carry a bare import past the
check. Either keep splitting off (worth a comment next to `splitting: false`) or make the check
follow relative `.js` imports within `dist/`.
