# P1.4 - Theme + locale resolution + link tokens

Row: `- [~] (A) P1.4 - Theme + locale resolution + link tokens, CSP-clean (plan: Config, Locale resolution, CSP)`

Tier: A

## Why

Theming is the one place site-supplied values reach inline style, so it is the CSP's weakest
point: every value is applied as a single `--consent-*` custom property through
`style.setProperty` on the root, and the tests spy on `setAttribute("style")` and `cssText` from
package code (mutation-checked: both assertions fail when either call is added to the theme).
Link tokens are the one place copy turns into markup, so they become `<a>` elements built from
the locale's `links`, never parsed HTML. Locale resolution itself landed in P1.2 (decision #18);
this package adds the locale-switch and link-rendering coverage. It also takes the P1.3 review's
advisories (id collisions, a runtime guard for Accept all / Reject all, settings
`aria-describedby`, forced-colours toggles, no `<body>` guard) and the P1.1 re-review's legacy
colour-syntax advisory, because they touch the same rendering and theme code.

### Findings

No P1. No P2.

- **P3** `src/core/banner.ts` `buttonOrder` / `firstLayer[id]()`: the runtime guard covers omitted
  and duplicate entries but not unknown ones; an unvalidated `buttons.order: ["acceptAll",
"rejectAll", "typo"]` makes `mount` throw (`firstLayer[id] is not a function`) and no banner
  shows. Nothing is stored, so no consent is implied, but filtering to `BUTTONS` before the
  required-append loop would make the guard complete.
- **P3** `test/unit/i18n.test.ts` "switching <html lang> changes every string": the expectation
  `["Session", "Stats", "Ads"].filter((s) => unchanged.includes(s))` is derived from the value
  under test, so it only asserts that unchanged strings are a subset of those names. An explicit
  expected list (or asserting the Swedish title/buttons directly) would read more clearly.
- **P3** `src/core/theme.ts`: `theme.vars` are applied after `radius`, `font`, `zIndex` and
  `width`, so a var silently overrides the dedicated key. This is the documented intent
  (decision #30); a one-line note in the config docs would save a host surprise.

### Questions

- None blocking. The CSP guarantee for theme values is held at unit level by the
  `setProperty`/`setAttribute("style")`/`cssText` spies; the zero-violation e2e assertion with a
  themed demo arrives with P1.7, as the plan places it.

### Acceptance

- Theme: every value is applied as one `--consent-*` property via `style.setProperty` on the root;
  no `cssText`, `setAttribute("style")`, `<style>`, `innerHTML` or `eval` anywhere in `src/`;
  defaults live in the bundled stylesheet on `.consent`, so inline values win as intended.
- Link tokens: built with `createElement("a")` and `textContent`; strings are never parsed as
  HTML; hrefs are already restricted to relative/http(s)/mailto/tel by validation; unknown
  tokens degrade to literal text.
- Locale resolution chain and per-locale links/hrefs covered by tests.
- Hardening (id prefixes, required buttons, `aria-describedby`, no-`<body>` guard, legacy colour
  syntax) is correct and tested.
