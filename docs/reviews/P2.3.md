## Why

The adapters only reach Astro sites through the integration, and the size promise ("a site that
uses neither ships neither byte") only holds if the page script is generated per config. The
integration now builds it from the validated config: `./gate` when `gateScripts` is `true`,
`./gtag` when `consentMode` is set, each installed after `mount`. The demo completes the plan's
Demo list (decision #40): one local gated script per category, the required one included, and a
visible `dataLayer`. The e2e suite now proves in Chromium what the unit tests cannot: no optional
script is requested before a choice, the required script runs and the required Consent Mode key
is granted in `default` before any choice, accept runs each script once, and a returning visitor's
stored grant runs at load. It also takes the P1.7 review advisories (reduced-motion transitions,
no-op withdraw leaves the cookie unchanged, the redundant smoke test removed). The version is
0.2.0; the tag follows the release steps on `main` after the merge.

### Findings

No P1 or P2 findings.

- **P3** `src/astro/integration.ts` / `src/astro/index.ts`: `pageScript` is a public export of
  `./astro` and its signature changed from `pageScript()` to `pageScript(config)` with a required
  argument. It is undocumented and not one of the plan's versioned contracts, so this is not a
  break under Releases, but either stop exporting it from the entry (tests can import
  `integration.ts`) or mention the change in `CHANGELOG.md`.
- **P3** `examples/astro/src/layouts/Demo.astro`: the mirror polls with `setInterval(…, 100)` for
  the page's lifetime. Rendering on `onConsent` plus a `demo:record`/load tick would be simpler and
  idle; harmless in a demo.

  rests on `waitForTimeout(300)`. Waiting for `networkidle` (as the first adapters test does)
  would make the "nothing else was requested" claim less timing-dependent.
