# P4.7 - Release 0.3.0

Row: `- [~] (A) P4.7 - Release 0.3.0, the first published version (plan: Releases)`

Tier: A (releasing)

## Why

0.3.0 is the first version of this codebase on npm (decision #62). npm already holds 0.1.0–0.2.1
from an earlier implementation of the same contract, while this repository's CHANGELOG has its
own 0.1.0–0.2.2 entries for local milestones that were never published, so a reader of npm must
be able to tell the two apart: a paragraph under the CHANGELOG's introduction says which is
which and names the two visible differences from the earlier npm versions (`data-type` instead
of `data-consent-type` on gated scripts, `bottom-center` as the default position), and the
0.3.0 entry repeats them as upgrade steps. The Unreleased entries of P4.0–P4.6 move under
`## [0.3.0] - 2026-10-22` with a fresh empty Unreleased above. The README gains a pointer to the
release procedure, the plan and the security policy; its requirements already say Astro >= 5.4
and Node >= 22 since P4.4. Publishing itself is the maintainer's: trusted publisher, tag, staged
approval and the deprecation of the earlier npm versions, in that order (`docs/releasing.md`).

### Findings

No P1 or P2 findings.

- **P3** `docs/reviews/P4.7.md`, _Why_, last sentence: it lists "the deprecation of the earlier
  npm versions" as a maintainer step "in that order (`docs/releasing.md`)", but
  `docs/releasing.md`, the plan and `docs/decisions.md` contain no deprecation step. Since the
  _Why_ becomes the commit body, either drop the deprecation from that sentence or add the step
  (with its `npm deprecate` command and range) to `docs/releasing.md` in a later package.
- **P3** `CHANGELOG.md`, 0.3.0 entry: "set `layout.position` if you relied on the old default"
  does not say what the old default was; naming it (`"center"`) makes the upgrade step
  actionable without opening the old README.
- **P3** `CHANGELOG.md`, 0.3.0 `Changed`: "now `astro >= 5.4` (was `>= 5`)" is true against the
  local 0.2.2 but not against npm 0.2.1, which already declared `>= 5.4`. The introduction
  covers this, so it is advisory.
- **P3** `README.md` "Available from v0.2.0" (Script gating, Consent Mode) and the v0.2.0 pointer
  under Validation: on npm, 0.2.0 is the earlier implementation, whose gate reads
  `data-consent-type`. A reader pinning `^0.2.0` from that sentence gets an attribute the README
  does not describe. Consider "from 0.3.0 on npm" wording in a later docs change.
